# Product

## Register

brand

## Platform

web

## Users

The presentation serves a mixed live audience of developers, DevOps engineers, product managers, and business stakeholders. It begins with concepts and outcomes that everyone can follow, then progressively adds enough technical depth to be most useful to developers and DevOps practitioners. Complex ideas are visualized with diagrams and charts rather than explained through dense prose.

## Product Purpose

This is a 10-minute presentation followed by a 45-minute hands-on demonstration. The opening maps the available GitHub agent workflows: Coding Agent for delegated implementation, Copilot code review for contextual pull request feedback, and custom GitHub Agentic Workflows for recurring repository-specific work. It then explains how teams create custom workflows, how GitHub Actions runs them, and how tools, permissions, and controlled outputs keep them bounded. The hands-on segment connects the capabilities in a guided story: Coding Agent creates a pull request, a developer changes it, Code Review Agent reviews the updated diff, and a custom workflow demonstrates broader automation. Success means attendees know which workflow fits which task and what to look for in the demo.

## Positioning

GitHub provides agent workflows for implementation, review, and recurring repository automation. Built-in agents cover common software-development moments; GitHub Agentic Workflows let teams define their own guarded, context-aware automation in GitHub Actions.

## Conversion & proof

- Primary CTA: choose the right GitHub agent workflow for the task, then follow the guided demonstration.
- Secondary CTA: create one bounded custom workflow for a recurring maintenance pain.
- The line to remember: delegate implementation, add contextual review, or describe your own workflow in Markdown.
- Belief ladder: agent workflows already support distinct implementation and review tasks; recurring repository work needs a customizable option; GitHub Actions makes contextual reasoning repeatable; compilation, isolation, scoped permissions, and safe outputs make custom workflows governable; teams can start with one focused workflow and expand from evidence.
- Proof on hand: a capability overview followed by a guided demonstration that connects Coding Agent, a manual pull request change, Code Review Agent, and a real custom workflow.

## Brand Personality

Confident, playful, and illuminating. The experience should feel like a GitHub-native live product story with its own stage personality: clear enough for business stakeholders, credible enough for engineers, and energetic without becoming AI hype.

## Anti-references

Do not make this feel like a dense documentation walkthrough or a default Microsoft PowerPoint corporate template. Avoid long walls of text, generic card grids, excessive code, ornamental terminal styling, and unsupported claims about autonomous AI.

## Design Principles

1. **Start with the maintenance gap.** Show why creating code is only the beginning and why review, tests, conventions, architecture, and documentation degrade without sustained attention.
2. **Reveal complexity progressively.** Let every new concept build on a visual model the audience already understands.
3. **Map the available workflows.** Explain what Coding Agent, Code Review Agent, and custom Agentic Workflows each do before the demo connects them.
4. **Make guardrails visible.** Treat security, permissions, safe outputs, and human review as core product value rather than caveats.
5. **End in action.** Hand directly into the guided technical demonstration instead of replaying its story on slides.

## Accessibility & Inclusion

Target WCAG 2.2 AA. Support complete keyboard navigation, visible focus states, reduced-motion preferences, and high contrast suitable for projectors and large rooms. Diagrams require accessible titles and descriptions, color must never be the only information carrier, and technical language should be introduced in plain terms before specialist vocabulary.
